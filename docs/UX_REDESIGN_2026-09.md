# UI/UX 全面檢視與重設計提案（2026-09）

> 狀態：已定案並實作（2026-09-06，P1–P3 一次完成）。第 1 節為改版前的診斷，第 2 節起為最終設計與實作對照。
> 目標場景：**一對多、多語**。講者在台上用筆電講中文，希望即時看到自己的繁中逐字稿，觀眾透過投影或第二螢幕看兩種自選外語（例如英文＋日文）。場地可能沒網路。第一次使用的人要全程知道「現在在做什麼、可能出什麼問題、還要多久」。

---

## 1. 現況診斷

### 1.1 視窗結構與「擠」的來源

| 現況 | 問題 |
|---|---|
| 三個對等視窗：控制 480×540、譯文 t1 900×320、譯文 t2 900×320 | 講者最需要的「自己的逐字稿」被放在**最小的視窗**，還要跟開始按鈕、狀態列、錯誤卡共用 540px 高度；實際逐字稿區約 300px |
| 兩個譯文視窗各自獨立 | 單螢幕筆電上三個視窗互相遮蓋；要投影得手動拖兩次；兩個視窗字級、釘選、無邊框各自設定，不同步 |
| 開始錄音按鈕 64px 高、字距 0.2em | 視覺重心在按鈕而不是內容；錄音中最需要看的是「字有沒有出來」 |
| 狀態列 12px：閒置／錄音中、計時、三個純圖示按鈕 | 資訊密度低但佔位；圖示無文字標籤 |
| 錯誤與提示有六種呈現：toast、mic 橫幅、錯誤卡、wizard 內警告、coach 泡泡、confirm 對話框 | 使用者要學六種東西各代表什麼 |

### 1.2 設定 modal

一個 448px 寬、可捲動的單欄，**17 個欄位**混在一起：

- 一次性設定：LLM 供應商、兩把金鑰、翻譯模型、總結模型
- 每場會議會動的：來源語言、譯文一、譯文二、辨識引擎、音源、麥克風裝置
- 很少動的：辨識延遲、同步口譯模式、閒置停止、會後自動總結、檔案

三種頻率的東西平鋪，每次開會前要調語言都得在 17 個欄位裡找。這是「太擠」最主要的來源。

### 1.3 Onboarding 現況

流程：歡迎 → 金鑰 → 準備辨識引擎（三步檢查表）→ 完成。

做得好的：檢查表有進度條、速度、剩餘時間、停滯偵測；金鑰有即時驗證；錯誤有 17 條友善翻譯規則。

不足的：

1. **沒有時間預估**。第一頁沒說整個流程要多久、模型下載要多久。
2. **沒有讓使用者選「怎麼用」**。一開始就要金鑰，但用本機辨識其實只需要 Anthropic key（翻譯用）；使用者不知道哪把是必要的。
3. **麥克風授權不是一個步驟**。授權對話框在 app 啟動時由 getUserMedia 觸發，時機跟 wizard 無關；被拒絕後只有主畫面橫幅。
4. **沒有「第一次成功」的時刻**。完成 wizard 後使用者不知道系統到底能不能用，要自己按錄音、自己講話、自己判斷。
5. **語言與視窗擺放沒教**。三個視窗彈出來，投影要拖哪個、怎麼全螢幕，wizard 只有一行文字。
6. **可能出的問題沒有事前說明**：磁碟空間（模型 1.5 GB）、公司防火牆擋 Hugging Face、金鑰餘額、Sequoia 的 quarantine。
7. 模型下載可背景進行是對的，但 wizard 關掉後進度只剩主畫面的 overlay，完成時沒有通知。

### 1.4 離線場景

- 本機 mlx-whisper 能離線辨識，**但翻譯與總結一定要網路**（Anthropic／OpenAI）。現在 UI 沒有任何地方說明這件事；沒網路時按開始，翻譯會一直失敗、錯誤卡疊上來。
- 沒有網路狀態指示，也沒有「偵測到離線，建議切本機引擎、僅顯示逐字稿」的引導。

### 1.5 譯文視窗呈現

- 譯文視窗淺色暖紙底，投影機上對比不足；沒有深色／高對比模式。
- 字級 20 到 64 手動調；沒有依視窗大小自動排版。
- 淡出效果（最近 5 句漸淡）對觀眾閱讀是好的，保留。
- 觀眾看不到原文；有些場合中文觀眾也想看逐字稿。

## 2. 目標與設計原則

1. **兩種視圖，三個視窗**：講者看「主控台」，觀眾看兩個各自獨立的「譯文視窗」。視窗架構不動，使用者自己把譯文視窗拖到各投影機（大型場地一窗一台）。
2. **逐字稿優先**：主控台六成面積給講者自己的即時逐字稿。
3. **狀態集中在一列 chip**：麥克風、辨識、翻譯、網路、落後，各自可點開看說明與一鍵動作，取代六種彈窗。
4. **離線 = 只有逐字稿**：翻譯暫停不報錯，網路恢復後自動繼續。
5. **中性打底，漸層點題**：底色是 Apple 系冷灰與純黑；藍→紫→粉→橘的 AI 漸層只用在「AI 正在工作」的四處，文字永遠單色。
6. **每個等待都回答三件事**：在做什麼、多久、可能出什麼問題與怎麼處理。

## 3. 最終設計與實作

### 3.1 主控台（`src/windows/ControlWindow.tsx`，視窗 960×640，最小 760×520）

```
┌ MeetingCast │ ●錄音中 3:21 │ 麥克風 ▮▮▮ 內建 │ 辨識 本機 │ 翻譯 en·ja │ 網路 線上 │        落後 1.8 s ┐
├──────────────────────────────────────────────────────────┬────────────────────────────┤
│ 即時逐字稿  繁體中文                                      │ 本場設定                    │
│                                                          │ 來源   [中文            ▾] │
│   （最近幾句，20px，最後一句加粗，                        │ 譯文一 [English         ▾] │
│     未完成的句子淡灰＋漸層游標）                          │ 譯文二 [日本語          ▾] │
│                                                          │ 辨識   [本機（離線可用） ▾] │
│                                                          │ 麥克風 [MacBook Pro   ▾][↻]│
│                                                          │ 估算   ≈ US$1.7 / 小時      │
│                                                          │ [開啟譯文視窗 ↗]            │
│                                                          ├────────────────────────────┤
│                                                          │ en  最近一句譯文（3 行）    │
│                                                          │ ja  最近一句譯文            │
├──────────────────────────────────────────────────────────┴────────────────────────────┤
│ [ ● 開始 ]（44px 漸層）   歷史會議  術語表  設定                              ⌘ ⇧ M │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

- 狀態列六個 chip，三態語意色（中性／橘／紅），點擊展開 popover：說明文字＋動作（打開系統設定、重新檢查、重試引擎、開啟譯文視窗、重新檢查網路）。啟動檢查表併入「辨識」chip 與逐字稿空狀態，不再有全畫面 overlay；未就緒時開始鍵顯示「準備中…」並停用。
- 「落後」= 最新一句 final 的音訊時間與錄音起算牆鐘的差，超過 4 秒轉橘。
- 「開啟譯文視窗」對已存在的視窗做 show + focus，被關掉的用 `WebviewWindow` 重建（`src/lib/windows.ts`，capability `core:webview:allow-create-webview-window`）。
- 開始鍵是主控台唯一的漸層色塊；錄音中變紅色「停止」。錄音脈動點用漸層（紅色保留給停止與錯誤）。

### 3.2 譯文視窗（`src/windows/TranslationWindow.tsx`，label 仍為 `t1` / `t2`）

- 預設純黑底白字；全局淺色選項 `[ui] translation_theme = "light"`（`.stage-light` 覆寫 stage-* token）。
- 外框「光暈」：2px 旋轉漸層邊＋內側柔光（`.aura-host`，16 秒一圈，`prefers-reduced-motion` 關閉）。錄音中亮、閒置暗、離線轉灰；`[ui] glow = false` 或無邊框模式關閉。
- 字級隨視窗高度自動：`clamp(20, innerHeight / 11, 64)`，A− / A+ 為持久化偏移（localStorage）。
- 標題列：語言原生名稱＋ A−、A+、釘選、無邊框、全螢幕（文字鈕）。錄音停止後顯示「已結束」並整體淡半。
- 離線且錄音中：底部一行「翻譯暫停，網路恢復後自動繼續」。

### 3.3 網路與離線行為（`src-tauri/src/netcheck.rs`）

- 背景每 20 秒（離線時每 5 秒）對翻譯供應商 API host 做 TCP connect 探測，狀態變化時發 `network:status {online}`；命令 `network_status` / `network_probe_now`。
- `translator::translate` 與 `interp::call_llm` 在離線時立即回傳 `offline: …`，不走 retry；前端把這類錯誤當「暫停」處理：該句存為 incomplete，不出錯誤卡。
- 雲端辨識 + 離線：開始前擋下並提示改用本機。

### 3.4 本場設定卡（`src/components/SessionSetupCard.tsx`）與設定（`src/components/SettingsModal.tsx`）

0.1.29 起「每場要調的」與「很少動的」分兩個地方，不再重複：

- **主控台右欄「本場設定」卡**（每場）：來源語言、譯文一／二、辨識引擎（本機／雲端）、麥克風裝置（＋↻）、費用估算、開啟／重新開啟譯文視窗。每個下拉改完立即 `set_config`，沒有儲存鍵；錄音中全部停用。辨識引擎選擇存 `[stt] backend`，重啟後保留。狀態列 chip 的 popover 不再開設定，只說明「到右欄改」。
- **設定 → 帳號**（一次）：翻譯引擎（OpenAI 預設／Anthropic）、OpenAI key、Anthropic key（各標「必要／選用」與用途）、翻譯模型、總結模型。
- **設定 → 進階**（很少）：譯文視窗外觀（純黑／淺色、光暈）、音源、辨識延遲（雲端時）、同步口譯模式（含費用確認）、閒置自動停止、會後自動總結、系統狀態（重新執行啟動檢查表／首次設定）、檔案。
- 0.1.27–0.1.28 曾有第三個「會議」分頁與卡片內容完全重複（五個「變更」連結都只是開那個分頁），試用後拿掉。

### 3.5 Onboarding 六步（`src/components/WelcomeWizard.tsx`）

頂部進度軌道永遠可見，含「已完成 n / 6 · 剩約 X 分」（模型步驟用即時下載 ETA）。每步固定三段：在做什麼／多久／可能問題。

| 步 | 內容 | 可能問題（事前寫出） |
|---|---|---|
| 0 歡迎 | 會發生什麼、總時間、可略過 | — |
| 1 選擇方式 | 本機辨識 vs 雲端辨識兩張卡片 | 沒網路→本機；非 Apple Silicon→雲端 |
| 2 麥克風 | 授權三態、打開系統設定、重新檢查 | 按了不允許；藍牙耳機；授權後仍失敗要重開 |
| 3 金鑰 | provider、key、即時驗證；雲端辨識另需 OpenAI key | 少貼字元；沒網路可先繼續；沒金鑰可略過 |
| 4 語音模型 | 檢查表＋進度；可先做下一步 | 磁碟不足；防火牆擋 huggingface；中斷續傳 |
| 5 語言與視窗 | 來源＋兩槽位；說明兩窗可各自拖到投影機；開啟譯文視窗 | 只有一台投影機；km 只能當譯文 |
| 6 試講一句 | 先寫入 config，開始試講，顯示逐字稿／各語譯文／落後秒數與檢查清單 | 沒出字時依序看麥克風、辨識、翻譯 chip |

進入第 6 步前把 provider／keys／language／`onboarding_complete: true` 寫入 config，中途當掉也不會重進 wizard。第一次啟動的判斷不變（未完成 onboarding 且無金鑰）；進階 → 系統狀態可隨時重跑。

### 3.6 訊息系統

- 狀態類 → chip 三態＋popover；一次性通知 → toast（右上，狀態列下方）；需要決定 → confirm 對話框；錯誤 → 逐字稿區上方一張可收合的錯誤卡（離線錯誤不顯示）。mic 橫幅、model-loading overlay、prewarm overlay 全部移除。

### 3.7 視覺（`src/App.css`）

- `paper-*` 名稱保留、值換成冷灰中性階（#FFFFFF → #F5F5F7 → … → #1D1D1F → #000000），所有既有元件自動換色。
- 新增 `ai-blue / ai-cyan / ai-violet / ai-pink / ai-orange` 與 `--ai-grad`、`--ai-grad-btn`、`--ai-conic`；utility：`.ai-text`、`.ai-fill`、`.ai-bar`、`.ai-dot`、`.ai-caret`、`.aura-host`。
- 語意色 `ok-* / warn-* / danger-*` 與漸層分開；`recording` 為純紅。
- 漸層只出現在四處：品牌字、開始鍵與錄音點、譯文視窗光暈、進度（下載條、onboarding 目前步、串流游標）。光暈透明度上限 0.42，週期 16 秒。

## 6. 已決定

1. 兩個譯文視窗維持獨立，不合併成舞台、不做停靠或螢幕偵測。
2. 譯文視窗預設純黑；深淺色為全局設定。
3. 光暈預設開，可在進階關閉。
4. 錄音脈動點用漸層；紅色留給停止鍵與錯誤。
5. 離線只保留逐字稿，翻譯暫停不報錯。
